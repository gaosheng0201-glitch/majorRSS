# 边界实验：不同领域 / 不同语言（2026-07-29 开始）

> 目的：作者提问"到底是向量还是筛选出问题"。用 4 个新任务做 2×2 对照，**预期先写下，几小时后用数据验证**——避免事后编故事。

## 设计

| 任务 | 领域 | 语言 | 精选源 |
|---|---|---|---|
| `rare-ALS-EN` | 罕见病(ALS) | 英文 | healthcare_medicine + academic_research（14 源） |
| `rare-ALS-ZH` | 罕见病(渐冻症) | 中文 | 同上（唯一变量=语言） |
| `sports-Ohtani-EN` | 体育明星 | 英文 | **无**（库里没有体育集合） |
| `sports-Ohtani-ZH` | 体育明星(大谷翔平) | 中文 | **无** |

第一个边界已经暴露：**预设库 19 个集合里没有任何体育类**——体育任务只能靠关键词裸奔，这正是 P4.1（来源发现）要解决的信息茧房问题的实例。

## 事前预测（待验证）

### 筛选层（预测：对中文近乎失效）

现有筛全部在英文 AI 语料上标定，对中文内容**结构性失效**：

1. **A4 自荐筛**：正则是英文（`I built`, `Show HN`, `my app`）→ 中文自荐（"我做了个…"）**不会被拦**。
2. **A5 歧义词筛**：只认 `gemini`/`grok` → 中文歧义（"大谷"是地名/姓氏、"道奇"是汽车品牌）**不覆盖**。
3. **P0.5 近重去重**：`normalize_title` 按空格分词，中文标题分不出词 → 跨标题 Jaccard 近 0 → **中文的转载去重基本不工作**。
4. **促销筛**：`/r/` 子版块规则只对 reddit 有效，中文源多为 gnews → **覆盖不到**。

→ **预测：中文任务的筛选拦截率显著低于英文任务**，噪音更多进入线索层。

### 向量层（预测：跨语言能合并，但过度合并是主要缺陷）

- changelog 记录跨语言同事件合并已验证（去均值 + 候选地板 0.05 + LLM 仲裁）。
- **但 AlphaFold 案例（线索 134）证明过度合并是真缺陷**：17 条成员里 16 条是"哈萨比斯游说华盛顿"、1 条是"AlphaFold 团队解散"，被并成一条。原因：仲裁器只在相似度 `< THREAD_HIGH_CONFIDENCE(0.55)` 时才介入，两条都是 "Google DeepMind" 新闻 → 相似度过高 → **静默合并，仲裁器从未被问**。
- → **预测：实体集中的话题（大谷翔平、ALS）过度合并率高**；同一实体的不同事件会被并进一条线索。

### 融合层（已确认的缺陷）

- **摘要用最新成员当标题**：`_fuse_thread` 按 `created_at DESC` 送成员，LLM 用 Source 1 当标题。AlphaFold（1/17，最新）因此成了标题，16 条的主线被降级成"此外"。
- → **预测：多事件线索的标题会随最新一条漂移**，与线索主体不符。

## 第一轮结果（2026-07-29，147 篇新语料）

### 🔴 最大发现：非英语关键词发现结构性失效（入口层，非向量非筛选）

`rare-ALS-ZH` 入库 **0 篇**，英文孪生 93 篇。根因：**Google News 按"版本(edition)"分区索引**，不带 `hl/gl/ceid` 即默认 en-US：

| 查询 | 无区域参数 | 有区域参数 |
|---|---|---|
| `渐冻症 when:7d` | **0 条** | 41 条中文 |
| `渐冻症` | 7 条（**全英文**） | 100 条中文 |
| `大谷翔平` | 100 条（**全英文**） | 35 条中文 |

**两个各自正确的设计撞出静默失效**：P0.1 的 `when:Nd` 新鲜度 + 非英语查询 = 归零。已修（按查询字形自动选版本：假名→ja、谚文→ko、汉字→zh），日/韩实测可用（JA 20 条、KO 11 条、大谷 JA 100 条）。

### ⚠️ 修完立刻暴露第二个问题：语言茧房（作者指出）

按字形选版本 → 中文查询**只走中文版** → 小众语言用户被锁在本语言信息里。实测证实**词只在自己的版本里有效**：

- `渐冻症` 查英文版 → **0 条**
- `ALS` 查中文版 → 38 条，但**全是英文结果**（还混进股票代码 ALS）

**设计裁决（作者定）**：*"不能因为语言小众就只获得本语言信息，也不能因为语言变成信息茧房。"*

**实现**：一个任务携带**多语言关键词**，每个词各自路由到自己的版本，同落一个任务 → 同一线索池 → 向量层做跨语言同事件合并。零新机制（复用 HYBRID 的多信号）。`rare-ALS-JA`（筋萎縮性側索硬化症 + ALS）、`rare-ALS-KO`（루게릭병 + ALS）按此建立。

> **遗留**：现在要用户**自己想到**加英文词。应用应当自动补齐跨语言别名 —— 归 **P4.1 发现引擎**（它提议的是数据/词，不是代码）。`rare-ALS-ZH` 保持单语作为对照，用来展示茧房效应。

### 向量层：过度合并已确证（AlphaFold 案例）

线索 134：16 条"哈萨比斯游说华盛顿" + 1 条"AlphaFold 团队解散"被并成一条。实测该条对线索质心的居中相似度 **0.547**，正卡在仲裁触发线 0.55 边缘 → 要么静默合并、要么 LLM 判错。**同实体+同机构的不同事件稳定落在 0.5–0.7 区间**，旧阈值把这一整类放过了。

**已修**：`THREAD_HIGH_CONFIDENCE` 0.55 → **0.80**，灰区大幅放宽；并加**每轮仲裁记账**（调用/判分/失败/因高置信跳过/因预算跳过），日志与返回值都有，花费按 `EventArbiter` 计入 Billing「成本构成」卡，便于跑几小时后统计占比。

### 标题问题：作者裁决 —— 不单独修

*"当分类合理以后，哈萨比斯和团队解散就是两条 feed，就不存在这个情况了。讲的是同一件事情就一个标题，除非后续有增量不然就保持。"* 正确：标题漂移是过度合并的**下游症状**，聚类修对即消失；"无实质增量则保持"已由迁移 0010 实现。**不引入独立的标题选择逻辑**（避免给症状打补丁）。

### 筛选层：工作正常，不是主要矛盾

AlphaFold 那 17 条全是正经新闻源与内容，**筛选层本就不该拦**。全语料回测：拦 622 条（11%），误杀已降到 ~2。

## 回测口径（几小时后按此测量）

1. **筛选拦截率**：每任务 `filtered / fetched`，按语言对比 → 验证预测 1
2. **入库语料的噪音率**：人工/规则抽样 → 中文是否更脏
3. **过度合并率**：成员 ≥3 的线索中，含多个不同事件的比例 → 验证预测 2
4. **跨语言合并**：同一事件的中英报道是否进同一线索（同任务内）
5. **标题代表性**：摘要标题是否代表线索多数成员 → 验证预测 3
6. **精选源效果**：有 scope 的罕见病任务 vs 无 scope 的体育任务，一手内容占比差异
