# 边界实验：不同领域 / 不同语言（2026-07-29 开始）

> 目的：作者提问"到底是向量还是筛选出问题"。用 4 个新任务做 2×2 对照，**预期先写下，几小时后用数据验证**——避免事后编故事。

## 设计

| 任务 | 领域 | 语言 | 精选源 |
|---|---|---|---|
| `rare-ALS-EN` | 罕见病(ALS) | 英文 | healthcare_medicine + academic_research（14 源） |
| `rare-ALS-ZH` | 罕见病(渐冻症) | 中文 | 同上（唯一变量=语言） |
| `sports-Ohtani-EN` | 体育明星 | 英文 | **无**（库里没有体育集合） |
| `sports-Ohtani-ZH` | 体育明星(大谷翔平) | 中文 | **无** |

第一个边界已经暴露：**预设库 19 个集合里没有任何体育类**——体育任务只能靠关键词裸奔，这正是 P4.1（来源发现）要解决的信息茧房问题的实例。

## 事前预测（待验证）

### 筛选层（预测：对中文近乎失效）

现有筛全部在英文 AI 语料上标定，对中文内容**结构性失效**：

1. **A4 自荐筛**：正则是英文（`I built`, `Show HN`, `my app`）→ 中文自荐（"我做了个…"）**不会被拦**。
2. **A5 歧义词筛**：只认 `gemini`/`grok` → 中文歧义（"大谷"是地名/姓氏、"道奇"是汽车品牌）**不覆盖**。
3. **P0.5 近重去重**：`normalize_title` 按空格分词，中文标题分不出词 → 跨标题 Jaccard 近 0 → **中文的转载去重基本不工作**。
4. **促销筛**：`/r/` 子版块规则只对 reddit 有效，中文源多为 gnews → **覆盖不到**。

→ **预测：中文任务的筛选拦截率显著低于英文任务**，噪音更多进入线索层。

### 向量层（预测：跨语言能合并，但过度合并是主要缺陷）

- changelog 记录跨语言同事件合并已验证（去均值 + 候选地板 0.05 + LLM 仲裁）。
- **但 AlphaFold 案例（线索 134）证明过度合并是真缺陷**：17 条成员里 16 条是"哈萨比斯游说华盛顿"、1 条是"AlphaFold 团队解散"，被并成一条。原因：仲裁器只在相似度 `< THREAD_HIGH_CONFIDENCE(0.55)` 时才介入，两条都是 "Google DeepMind" 新闻 → 相似度过高 → **静默合并，仲裁器从未被问**。
- → **预测：实体集中的话题（大谷翔平、ALS）过度合并率高**；同一实体的不同事件会被并进一条线索。

### 融合层（已确认的缺陷）

- **摘要用最新成员当标题**：`_fuse_thread` 按 `created_at DESC` 送成员，LLM 用 Source 1 当标题。AlphaFold（1/17，最新）因此成了标题，16 条的主线被降级成"此外"。
- → **预测：多事件线索的标题会随最新一条漂移**，与线索主体不符。

## 回测口径（几小时后按此测量）

1. **筛选拦截率**：每任务 `filtered / fetched`，按语言对比 → 验证预测 1
2. **入库语料的噪音率**：人工/规则抽样 → 中文是否更脏
3. **过度合并率**：成员 ≥3 的线索中，含多个不同事件的比例 → 验证预测 2
4. **跨语言合并**：同一事件的中英报道是否进同一线索（同任务内）
5. **标题代表性**：摘要标题是否代表线索多数成员 → 验证预测 3
6. **精选源效果**：有 scope 的罕见病任务 vs 无 scope 的体育任务，一手内容占比差异
