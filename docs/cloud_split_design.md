## 0. 一句话

**同一个后端，换个地方跑；桌面端变客户端；身份留在本机。** 云端跑不需要凭证的那 90%（RSS/官方源/gnews/页面监控/登记库 + 语义 + 融合 + 记忆），本机只跑需要你的身份的那 10%（授权账号、浏览器），两边写同一套线索模型。

## 1. 为什么是分体而不是"整个搬上云"或"整个留本机"

| 形态 | 全天候 | 你的凭证在哪 | 数据中心 IP 抓社交平台 | 结论 |
|---|---|---|---|---|
| 全留本机（现状 + 开机自启） | 合盖即断（8/21–22 实测两天各跑 1–2 小时） | 本机 | — | 地板，保留 |
| 全搬云端 | ✅ | **云端**——你最怕的封号风险从本机转到服务器 | 更易被拦、登录态更易被判异常 | 否决 |
| **分体（本文）** | ✅ 公开源全天候 | **本机** | 云端只碰公开源 | 采用 |
| 多租户托管 | ✅ | 平台 | 同上 + 合规 | R7 Phase 2 |

分体和愿景的三条硬约束完全一致：本地优先（身份/凭证不出本机）、BYOK（key 在你自己的服务器）、纯 RSS 地板（无 key 的云端实例照样有价值）。

## 2. 拓扑

```text
┌──────────────── 你的常驻机（NAS / $5 VPS / 树莓派 / 闲置笔记本）────────────────┐
│  majorss-backend（Docker）  = 现在的 backend/main.py 原样                         │
│    调度 · 公开源抓取 · 语义(全局线索/透镜/故事线) · 融合 · 涌现源 · 页面监控 · 记忆   │
│    SQLite 主库（source of truth） · 加密的 LLM key（config.dat 同机制）             │
│    绑定 0.0.0.0（仅 REMOTE_MODE）· Bearer token 鉴权 · 私网(Tailscale) 或 TLS      │
│    通知推送：ntfy / Telegram / 邮件（桌面不在线也能收到）                            │
└──────────────────────────────▲──────────────────────────────────────────────┘
                               │ HTTPS/私网：现有 /api 全部 + 新增 /api/intake
┌──────────────────────────────┴──────────────────────────────────────────────┐
│  桌面端（Tauri）                                                                │
│    模式 A（默认，现状）：连本机 127.0.0.1:8765，一切如旧                            │
│    模式 B（远程）：连远端；本机后端降为"私有通道代理"——                              │
│      只跑授权路由（agentic + cookie），抓到的条目 POST 到远端 /api/intake            │
│      cookie / storage_state / AuthProfile **永不上传**，离线时条目本地排队           │
└──────────────────────────────────────────────────────────────────────────────┘
```

## 3. 关键设计决策

1. **主库在远端**。线索/故事线/透镜/涌现源都是有状态的，必须只有一个真相。切换到远程模式时把本机 `major_rss.db` **复制上去一次**（SQLite 单文件；迁移在启动时幂等跑），之后本机不再是主库。回退到本地模式 = 反向复制一次。**不做双向同步**（复杂度不值，且违背"一个真相"）。
2. **私有通道条目级回传**。本机授权抓取的产物走 `POST /api/intake`（条目：url/title/content/published_at/route 元数据/`from_account`/tier），远端按现有 normalizer 入库盖章。远端**只收结果，不知道凭证**。回传失败进本地队列（SQLite 表），联网后补发；去重靠 URL 全局唯一，重发无害。
3. **鉴权最小可用**：`MAJORSS_API_TOKEN`（启动时生成/配置，桌面端设置页填一次），Bearer 头；`REMOTE_MODE=1` 才绑定 0.0.0.0，否则维持 127.0.0.1 无鉴权（现状不变）。传输安全二选一：**Tailscale**（推荐：零公网暴露、零证书运维，NAS/树莓派场景最自然）或 反向代理 + TLS（VPS 公网）。
4. **通知不依赖桌面**。新增 `notify_service`：告警（共振/高关注/监控 material 更新）同时投递到 Tauri 通知（桌面在线时）和服务器侧渠道（ntfy 最省事——一个 topic URL；Telegram bot / 邮件作可选）。渠道配置存远端。
5. **LLM key 在远端**，沿用 `config.dat` Fernet 加密 + 0600；预算刹车 `LLM_DAILY_TOKEN_BUDGET` 照旧。是你自己的机器，BYOK 语义不变。
6. **同一镜像，两种配置**：官方无头实例（[official_feed_automation.md](official_feed_automation.md)）= 无授权、无私人数据、发布到 onlyforbots；私人云端实例 = 有 key、有私人目标、**无 cookie**。差别只在环境变量与数据，代码零分叉。
7. **版本**：镜像 tag = 应用版本；桌面端与远端版本不一致时提示（`/health` 已返回版本），迁移向前兼容由现有幂等迁移保证。

## 4. 永远不上云端的（硬边界，沿用官方实例的边界）

AuthProfile / cookie / storage_state；Tauri updater 私钥。被攻破的最坏损失 = 你的 LLM key 预算 + 你的关注清单泄露（不含任何平台身份）。

## 5. 分期（每刀独立可合入）

| 刀 | 内容 | 量 |
|---|---|---|
| C0 | `deploy/Dockerfile`（python 镜像，比 PyInstaller 更简单）+ `REMOTE_MODE` 绑定 + token 鉴权中间件 + `/health` 带版本 | 半天 |
| C1 | 桌面端设置页"远程后端"（地址 + token），client.ts baseURL 可配置，连接测试 | 半天 |
| C2 | `POST /api/intake` + 本机私有通道代理模式（只跑授权路由 → 回传 → 离线队列） | 1–2 天 |
| C3 | `notify_service` + ntfy 渠道（Telegram/邮件后补） | 半天 |
| C4 | 一键脚本 / compose 文件 / Tailscale 说明；数据库搬迁与回退步骤 | 半天 |

C0+C1 即可用（公开源全天候 + 桌面远程看），C2 才把人物雷达接进来，C3 才算"agent 式提醒"。

## 6. 验收

- 合盖 24 小时后打开桌面端：线索连续、无断档（对照 8/21–22 的空窗）。
- 远端只有公开源；`AuthProfile` 表为空；本机授权抓取的条目出现在远端线索里，且 `from_account=True`。
- 桌面不在线时，一次共振告警能到手机（ntfy）。
- 官方无头实例与私人云端实例用同一镜像启动，仅环境变量不同。
